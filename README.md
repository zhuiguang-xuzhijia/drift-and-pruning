# 漂移的必然性与修剪定向

> **一句话**：漂移不能消除；但"忘什么、先想起什么"是可编程的 —— 而漂移的方向，就由这个程序决定。
>
> **The inevitability of drift — and steering it by memory pruning.**

## 这是什么

一份**只有理论 + 四份可跑脚本 + 统计量**的记录。
讨论两个问题：

1. **AI 漂移为什么是必然的**（以及为什么"更长上下文"不解决它）
2. **能不能用"记忆修剪"给漂移定向**（忘什么、先想起什么，由规则决定）

**这里不含**：真实用户语料、任何个人数据、模型权重。
所有实验都在合成语料与**一位作者的对话记录**上完成，后者的原文不公开，只公开统计量。

---

## 三条核心结论

```
① 漂移不是"越说越偏"，是「遗忘」+「填空」两个离散事件的叠加。
   300 轮实测：召回 13/20 → 1/20，之后 220 轮贴地不恢复。
   形状是【阶跃 + 饱和】，不是二次曲线，也不是线性衰减。

② 长上下文只延后掉落，不阻止掉落。
   窗口 8/20/50 三档：套话率 22/29/50%，探针相似度基本不动。
   唯一改变"掉不掉"的，是把记忆搬到窗口之外（账本 + 折叠锚点）。

③ 既然遗忘必然发生，"漂移方向"就由修剪规则决定：
   分域（先收窄）→ 权重（先提谁）→ 絮语（不进记忆）。
   实测：权重 ≥0.6 的条目 0/10 → 16/47；未分类 50.0% → 29.8%；逐句保留率 76.6%。（n=1）
```

**边界**：第 ③ 条里"修剪决定漂移方向"是【推断】——
我们测到的是"修剪改变了保留与检索"，**没有直接测到漂移方向**。详见论文 §六。

## 怎么复核

```bash
# 1. 曲线（需要模型 API；把 key 写进环境变量 DEEPSEEK_KEY）
python -X utf8 code/drift_curve.py 300

# 2. 逐句对账（离线，读自己的账本）
python -X utf8 code/recall_audit.py

# 3. 域看板（离线）
python -X utf8 code/domain_board.py

# 4. 修剪三件套的实现本身（离线，自带自测）
python -X utf8 code/fact_log.py
```

**四个脚本都只依赖标准库。**
code/fact_log.py 自带自测：python -X utf8 code/fact_log.py，会演示切句→分域→打分→写入→检索→絮语拦截。
它的 折叠() 需要外部注入一个模型函数（折叠(uid, 调模型=你的函数)），其余全部离线可跑。
数据目录可用环境变量 FACT_LOG_DIR 指定，默认放在脚本旁边的 对话日志/事实。
